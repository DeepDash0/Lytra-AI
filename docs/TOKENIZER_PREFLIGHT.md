# Lytra V1 — Independent Tokenizer Alignment and Technical Preflight

These local tools check consistency between **raw source samples** and a producer's **pre-packing content token IDs**. They cannot certify training readiness on their own.

## 1. Prepare a privacy-preserving alignment sample

Prepare two **private**, local UTF-8 JSONL files from an independently chosen subset of the same source documents:

Source sample, one JSON object per line:

    {"text":"Example sentence"}

Producer sidecar, one JSON object per line:

    {"source_sha256":"<sha256 of the exact UTF-8 bytes of the original text>","token_ids":[...]}

`source_sha256` is SHA-256 over **the exact UTF-8 text bytes without NFC, whitespace trimming, or newline normalization**. This deliberately differs from the normalized deduplication digest in `dataset_audit.py`. The producer must export token IDs after tokenization but before adding BOS/EOS or packing padding. Never use a fake sidecar generated by the independent validator; it must come from the actual producer/packer pipeline. Both files should contain each sampled document exactly once. The script is bounded to 10,000 records by default; use smaller samples if RAM is constrained.

## 2. Check pinned tokenizer

Obtain the independently approved SHA-256 for the frozen, versioned Lytra tokenizer artifact from the project's authoritative record. The tokenizer is not included in the public GitHub repository. Do not use the file's freshly computed hash as the independent trust pin.

Install the tested dependency in an isolated local environment with `python -m pip install -r requirements-audit.txt`, then run:

    python -m scripts.tokenizer_alignment --sources <private_source_sample.jsonl> --emitted <private_producer_sidecar.jsonl> --tokenizer-json <frozen_tokenizer.json> --expected-tokenizer-sha256 <trusted_64_hex_sha> --vocab-size 65536 --output artifacts/alignment_report.json

Success produces `PASS_SAMPLE_ALIGNMENT` with aggregate counts. Reordered samples are okay, but extra, missing, duplicate, malformed or mismatched records fail. The report never contains source text, token IDs, raw source fingerprints or local file paths.

## 3. Evaluate technical preflight

The combined preflight is fail-closed. To check what is still missing locally:

    python -m scripts.preflight --output artifacts/preflight_local.json

Expected result without artifacts is `BLOCKED` (exit code 2). Once source audit, packed-batch audit, independent tokenizer alignment and shard manifests have been verified, run:

    python -m scripts.preflight --dataset-report <dataset_report.json> --packing-report <packing_report.json> --alignment-report <alignment_report.json> --replay-report <replay_report.json> --manifest <private_manifest.json> --shard-root <private_shards_folder> --expected-tokenizer-sha256 <trusted_64_hex_sha> --min-content-tokens 10000000 --output artifacts/preflight_local.json

`PASS_TECHNICAL_ONLY` means **only** the declared technical checks are consistent. Preflight never launches a training process and always leaves `production_ready=false` until a separate release process covers verified data rights, immutable full manifests, real TPU 17-step streaming/resume, durable checkpoint restore, and final production schedule. A matching artifact SHA cannot prove the packer or source producer was honest; the source and producer-side sample captures must be independently produced.

## 4. Local verification

    python -m unittest discover -s tests -q

    python -m scripts.smoke_packing

    python -m scripts.smoke_alignment

All tests use synthetic data. Real source samples, model checkpoints, private manifests, credentials and tokenizer files must remain outside the Git repository.

The preflight also requires a successful strict replay report described in [RESUME_GATE.md](RESUME_GATE.md), with the same tokenizer pin and the same canonical `entries_sha256` as the verified shard manifest. This is a **declared-state consistency check**, not the outstanding real-data TPU gate.
